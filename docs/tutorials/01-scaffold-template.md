# Build a Scaffold Template from Scratch

In this tutorial you'll create a complete TAG template for a weather API — first in Python (Flask), then in Go (net/http). By the end you'll have a reusable template with variables, conditionals, hooks, generators, and bundles.

Working examples live in `examples/weather-api-python/` and `examples/weather-api-go/`.

## 1. Create the Template Directory

A TAG template is a directory with a `tag.template.json` config and a project folder whose name is a path placeholder.

### Python

```bash
mkdir -p weather-api-python/'{{ vars.project_name }}'
```

### Go

```bash
mkdir -p weather-api-go/'{{ vars.project_name }}'
```

The `{{ vars.project_name }}` directory is renamed at scaffold time to whatever the user provides.

## 2. Define Variables

Create `tag.template.json` in the template root. This declares the template's name, description, and the variables users will be prompted for.

### Python

```json
{
  "name": "Weather API (Python)",
  "description": "A simple weather API built with Flask",
  "version": "1.0.0",
  "vars": {
    "project_name": "weather-api",
    "description": {
      "type": "string",
      "prompt": "Project description",
      "default": "A simple weather API"
    },
    "api_provider": {
      "type": "choice",
      "prompt": "Weather data provider",
      "options": ["Mock", "OpenWeatherMap", "WeatherAPI"],
      "default": "Mock"
    },
    "use_docker": {
      "type": "boolean",
      "prompt": "Include Dockerfile?",
      "default": false
    },
    "_package_name": "{{ vars.project_name | snake }}"
  }
}
```

### Go

```json
{
  "name": "Weather API (Go)",
  "description": "A simple weather API built with net/http",
  "version": "1.0.0",
  "vars": {
    "project_name": "weather-api",
    "description": {
      "type": "string",
      "prompt": "Project description",
      "default": "A simple weather API"
    },
    "api_provider": {
      "type": "choice",
      "prompt": "Weather data provider",
      "options": ["Mock", "OpenWeatherMap", "WeatherAPI"],
      "default": "Mock"
    },
    "use_docker": {
      "type": "boolean",
      "prompt": "Include Dockerfile?",
      "default": false
    },
    "module_path": {
      "type": "string",
      "prompt": "Go module path",
      "default": "github.com/example/{{ vars.project_name | kebab }}"
    }
  }
}
```

Key concepts:

- **Short form** (`"project_name": "weather-api"`) — a string default, prompted with a text input.
- **Long form** (`"description": { "type": "string", ... }`) — explicit type, prompt text, and default.
- **Choice** (`"api_provider"`) — user selects from a list.
- **Boolean** (`"use_docker"`) — yes/no confirmation.
- **Derived** (`"_package_name": "{{ vars.project_name | snake }}"`) — computed, never prompted. The `_` prefix makes it private.
- **Evaluated default** (`"module_path"`) — has both a `prompt` and a template expression default. The user sees the resolved value as a suggestion and can override it.

## 3. Create Template Files

All text files inside the template are processed through the Jinja2 engine — use `{{ vars.* }}` expressions and control structures directly. Binary files (images, etc.) are copied as-is.

### Python — `{{ vars.project_name }}/app.py`

~~~jinja2
# Generated by TAG — {{ vars.project_name }}
from flask import Flask, jsonify

app = Flask(__name__)


{% if vars.api_provider == "OpenWeatherMap" %}
OPENWEATHERMAP_API_KEY = "your-api-key-here"
{% elif vars.api_provider == "WeatherAPI" %}
WEATHERAPI_KEY = "your-api-key-here"
{% endif %}


def get_weather(city: str) -> dict:
    """Fetch weather data for a city."""
{% if vars.api_provider == "Mock" %}
    return {
        "city": city,
        "temperature": 22.5,
        "condition": "Sunny",
        "humidity": 45,
    }
{% endif %}


@app.route("/weather/<city>")
def weather(city: str):
    data = get_weather(city)
    return jsonify(data)


# ROUTES


if __name__ == "__main__":
    app.run(debug=True, port=5000)
~~~

### Go — `{{ vars.project_name }}/main.go`

~~~jinja2
// Generated by TAG — {{ vars.project_name }}
package main

import (
	"encoding/json"
	"fmt"
	"log"
	"net/http"
)

type WeatherData struct {
	City        string  `json:"city"`
	Temperature float64 `json:"temperature"`
	Condition   string  `json:"condition"`
	Humidity    int     `json:"humidity"`
}

func getWeather(city string) WeatherData {
{% if vars.api_provider == "Mock" %}
	return WeatherData{
		City:        city,
		Temperature: 22.5,
		Condition:   "Sunny",
		Humidity:    45,
	}
{% endif %}
}

func weatherHandler(w http.ResponseWriter, r *http.Request) {
	city := r.PathValue("city")
	if city == "" {
		http.Error(w, "city parameter required", http.StatusBadRequest)
		return
	}
	data := getWeather(city)
	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Encode(data)
}

// ROUTES

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /weather/{city}", weatherHandler)
	fmt.Println("Server listening on :8080")
	log.Fatal(http.ListenAndServe(":8080", mux))
}
~~~

Notice:

- **`{{ vars.* }}`** is the namespace for all variables in scaffold templates.
- **`{% if %}`/`{% elif %}`/`{% endif %}`** controls conditional output.
- **`# ROUTES`** / **`// ROUTES`** is a marker for generator injection (step 7).

## 4. Add Post-Scaffold Hooks

Hooks run shell commands after scaffolding. Add them to `tag.template.json`:

### Python

```json
{
  "hooks": {
    "post_scaffold": ["pip install -r requirements.txt"]
  }
}
```

### Go

```json
{
  "hooks": {
    "post_scaffold": ["go mod tidy"]
  }
}
```

> **Note:** When scaffolding remote templates, TAG prompts the user before running hooks. Use `--accept-hooks` to skip the prompt, or `--no-hooks` to disable hooks entirely.

## 5. Lint the Template

Validate your template before using it:

```bash
tag template lint ./weather-api-python
```

This checks three things:
1. `tag.template.json` against the JSON Schema
2. All template files for Gonja syntax errors
3. `{{ vars.* }}` references match declared variables

Fix any errors before proceeding.

## 6. Scaffold Locally

Test your template by scaffolding a project:

```bash
# Interactive — prompts for each variable
tag scaffold ./weather-api-python my-weather-app

# Non-interactive — uses defaults, overrides with -m
tag scaffold ./weather-api-python my-weather-app --no-input -m project_name=my-app
```

Check the output directory — you should see your project with all variables resolved and conditionals applied.

## 7. Add an Endpoint Generator

Generators let users add code to a scaffolded project. They live in `_generators/` in the template and become available when the template is installed to the library via `tag lib add`.

Generator files use **frontmatter** (not YAML — simple `key: value` lines) and keep their natural file extension.

### Python

Create `_generators/endpoint/handler.py`:

```
---
to: {{ name | snake }}.py
desc: Create a new endpoint handler
---
from flask import jsonify


def get_{{ name | snake }}(city: str) -> dict:
    return {
        "city": city,
        "{{ name | snake }}": "placeholder",
    }
```

Create `_generators/endpoint/register_route.py` to inject a route:

```
---
to: app.py
inject: true
after: "# ROUTES"
desc: Register the new endpoint route
---

@app.route("/{{ name | kebab }}/<city>")
def {{ name | snake }}(city: str):
    from {{ name | snake }} import {{ name | snake }}_handler
    return {{ name | snake }}_handler(city)
```

### Go

Create `_generators/endpoint/handler.go`:

```
---
to: {{ name | snake }}.go
desc: Create a new endpoint handler
---
package main

import (
	"encoding/json"
	"net/http"
)

type {{ name | pascal }}Data struct {
	City string `json:"city"`
	{{ name | pascal }} string `json:"{{ name | snake }}"`
}

func {{ name | camel }}Handler(w http.ResponseWriter, r *http.Request) {
	city := r.PathValue("city")
	data := {{ name | pascal }}Data{City: city, {{ name | pascal }}: "placeholder"}
	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Encode(data)
}
```

Create `_generators/endpoint/register_route.go` to inject a route:

```
---
to: main.go
inject: true
after: "// ROUTES"
desc: Register the new endpoint route
---
	mux.HandleFunc("GET /{{ name | kebab }}/{city}", {{ name | camel }}Handler)
```

Key differences from scaffold templates:

- **`{{ name }}`** is the CLI argument (`tag generate endpoint <name>`).
- **`{{ vars.* }}`** still works — for meta variables from `-m` flags or `.tagconfig.json`.
- **`inject: true`** + **`after: "// ROUTES"`** inserts code after the marker line in an existing file.
- **Frontmatter is NOT YAML** — simple `key: value` parser, no nesting or arrays.

## 8. Add a Bundle

Bundles group generators to run them together. Create `_generators/_bundles/full-endpoint.json`:

```json
{
  "name": "full-endpoint",
  "generators": [
    { "name": "endpoint" }
  ]
}
```

After scaffolding, users can run:

```bash
tag generate full-endpoint humidity
```

This runs the `endpoint` generator, creating the handler file and injecting the route — all in one command.

> **Tip:** Bundles are auto-resolved — no `--bundle` flag needed. `tag generate` checks both generators and bundles.

## 9. Install to Library

Install your template for easy reuse:

```bash
# Install with a custom name
tag lib add ./weather-api-python --as weather-py

# List installed templates
tag lib ls

# Scaffold from library
tag scaffold weather-py my-new-app
```

Templates in the library can be scaffolded by name from anywhere.

```

├── tag.template.json
├── .tagignore
├── {{ vars.project_name }}/

│   ├── requirements.txt
│   ├── README.md
│   └── Dockerfile
└── _generators/
    ├── endpoint/
    │   ├── tag.template.json
    │   ├── handler.py
    │   └── register_route.py
    └── _bundles/
        └── full-endpoint.json
```
